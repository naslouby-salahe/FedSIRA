# Dataset adapter equivalence review

Compared `datasets/nbaiot/prepare.py`, `datasets/ciciot2023/prepare.py`, both schema modules, `datasets/common.py`, and `datasets/role_split.py` against Roadmap §§9–11 and the production adapter tests on 2026-09-26.

| Concern | Shared owner or adapter implementation | Audit result |
|---|---|---|
| Role names and evidence-role classes | `Role` and the shared supported/target role order in `datasets/common.py`. | One typed vocabulary; no duplicate string registries. |
| Role boundaries and guard gaps | Both adapters construct `RoleWindow` values from the primary role interval configuration and use the shared role-window/SQL-window helpers. N-BaIoT assigns within source streams; CIC assigns after stable-ID ordering within each label × pseudo-domain group as §11 requires. | The interval math and boundary conventions are shared; the grouping/order differences are explicit dataset contracts. Both adapter suites test boundaries, gaps, and deterministic assignment. |
| Role-specific caps | Both call `sampling_cap_for_role` with the same authoritative `SamplingCapsPerDomain`. N-BaIoT applies deterministic source-row ranking; CIC applies deterministic SQL ranking over its stable IDs and pseudo-domains. The SQL framed-hash implementation has parity fixtures against its reference implementation. | Cap values and role semantics have one owner. Ranking inputs differ because the datasets have different identity and grouping contracts; no copied cap table or post-outcome choice exists. |
| Feature scaling | Both call `fit_feature_moments` and `standardized_feature_sql`; the scaler population is supported-class Anchor Train only. | Shared formula and transformation owner. Adapter fixtures check the fitting population, finite values, and clipping. |
| Stable identities | N-BaIoT uses shared `compute_sample_id`; CIC uses native DuckDB SHA-256 over the same framing contract through `stable_row_id_sql`. | Dataset prefixes/relative paths differ by declared dataset identity. CIC SQL framing and pseudo-domain results have parity fixtures; production output audits verify unique IDs and manifest agreement. |
| Labels and schemas | N-BaIoT resolves device/family/file tokens in `nbaiot/schema.py`; CIC resolves normalized release headers and per-attack directory labels in `ciciot2023/schema.py`. | Rules remain dataset-specific as required by the different raw representations; neither adapter copies the other's parser. CIC canonical collisions and target-family aliases are explicitly validated. |
| Predictor and row construction | Each adapter validates its own raw header and constructs numeric inputs from its actual schema. Shared SQL quoting, CSV relation, feature scaling, Parquet writing, and sidecar/artifact operations come from `datasets/common.py` and artifact/path owners. | Dataset-specific extraction is separated from common construction and writing; no duplicate common feature formula was found. |

Relevant regression coverage includes `tests/unit/datasets/test_common.py`, both adapter preprocessing suites, role-manifest fixtures, CIC SQL framing/pseudo-domain/sampling parity tests, and independent prepared-output verification for all 2,208 production views. The implementation preserves the declared primary and secondary role constructions and observed schemas without retuning caps or thresholds.

No shared split, eligibility, cap lookup, scaling, common artifact identity, or feature-standardization implementation was duplicated with divergent semantics. The distinct grouping, raw label rules, and deterministic row-ranking inputs are justified dataset-specific architecture, not implementation drift.
